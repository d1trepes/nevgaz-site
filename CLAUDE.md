# CLAUDE.md — инструкция для разработки сайта НевГаз

Ты делаешь **демо-версию сайта** для компании **НевГаз** (Невинномысск): газификация, отопление, водоснабжение и электрика частных домов под ключ. Демо показываем клиенту, чтобы заключить договор — главная должна выглядеть как дорогой, живой, проработанный сайт. Срок — один рабочий день, поэтому качество главной важнее количества страниц.

## Прочитай перед началом (в этом порядке)
1. `docs/01-company-brief.md` — кто клиент, услуги, контакты, цены.
2. `docs/02-homepage-spec.md` — **главный документ**: блоки главной, тексты, поведение на десктопе и мобилке.
3. `docs/03-design-system.md` — цвета, шрифты, компоненты, движение. Токены уже в `src/styles/tokens.css`.
4. `docs/04-assets.md` — какие фото куда; `docs/05-ai-media-prompts.md` — чего не хватает.
5. `docs/06-mobile-and-performance.md` — адаптив, бюджет скорости, доступность.
6. `docs/07-sitemap.md` — остальные страницы (пока заглушки).
7. `references/` — референсы от заказчика (скриншоты/ссылки). Если есть — они главнее моих вариантов хиро в спеке; бери из них подачу, ритм, анимации, но не копируй один в один.

## Стек
- **Astro 7** (уже установлен), статическая сборка, многостраничник через `src/pages`.
- Стили: обычный CSS + CSS-переменные из `tokens.css`, scoped `<style>` в компонентах. Без Tailwind и UI-китов.
- JS: ванильный, островки только где нужно. Разрешено: `gsap` (+ScrollTrigger) для хиро-схемы и таймлайна, `lenis` — опционально. Больше зависимостей не тащить без причины.
- Шрифты: `@fontsource/roboto-condensed`, `@fontsource/manrope` (self-host).
- Картинки: только `astro:assets`.

## Арт-дирекшн: работаем как опытный арт-директор, а не как нейросеть
Сайт не должен выдавать, что его сделал ИИ по шаблону. Тест для каждого блока: **если его можно перенести на сайт стоматологии или SaaS, поменяв только слова, — переделать.**

**Запрещено (типичные ИИ-шаблоны):**
- Надзаголовки (eyebrow) над H1/H2: мелкий капс с точкой, чёрточкой или в пилюле («● Наши услуги», «— О компании»). Ни одного на сайте.
- Точки-маркеры, бейджи-пилюли «● Работаем 24/7», эмодзи в интерфейсе, иконки в цветных кружках/квадратах над каждым пунктом.
- Ряды из 3–4 одинаковых карточек «иконка → заголовок → две строки текста» в каждой секции. Каждая секция — своя композиция.
- Схема «заголовок по центру + подзаголовок + две кнопки» как единственный приём. Всё по центру.
- Градиентные блобы, размытые цветные пятна-«свечения» на фоне, glassmorphism, неон, фиолетово-синие градиенты, сетка-«чертёж» на каждом тёмном фоне.
- Одинаковые скругления, тени и отступы у всего подряд; одинаковая высота всех секций.
- Выдуманные счётчики («1000+ довольных клиентов», «15 лет опыта»), если их нет в брифе.
- Слова: «инновационный», «решения», «лидер», «качество и надёжность», «индивидуальный подход», «команда профессионалов», «Почему выбирают нас», «Мы — это…». Конструкции «это не просто X, это Y», триады через запятую ради ритма, восклицательные знаки.
- Отзывы в карточках с огромными кавычками и аватарками-кружками с инициалами по шаблону.
- Стоковые улыбающиеся люди, люди в касках «показывают большой палец».

**Как делать вместо этого:**
- Отталкиваться от материала их работы: реальные фото, жёлтые газовые трубы с отводами 90° и хомутами, кирпич и шлакоблок, счётчики, дымоходы из нержавейки, маркировка «Огнеопасно газ». Это и есть визуальный язык бренда.
- Смелый масштаб типографики: заголовок может занимать половину экрана, цифры цены — быть огромными. Контраст масштабов внутри блока.
- Асимметрия и редакторская вёрстка: фото разного размера, наложения, выход элементов за сетку, разный ритм секций (плотная → воздушная → плотная).
- Один сильный приём на экран, а не пять слабых. Анимация — только там, где она что-то объясняет (труба ведёт, пламя загорается, цифры счётчика крутятся).
- Подписи к фото как в техдокументации: «Ввод газа, фасад, Невинномысск». Без пафоса.
- Тексты — как говорит толковый мастер по телефону: коротко, конкретно, на «вы», с цифрами и сроками.

## Правила
- Тексты и контакты — из `company.json`. Значения `TODO` на сайте не показывать: либо скрыть элемент, либо нейтральная формулировка.
- Не выдумывать факты о компании (годы, количество объектов, лицензии, «бесплатно»). Если нужна цифра для красоты — только из брифа.
- Каждый блок сразу делать **mobile-first** и проверять на 375px и 1440px до перехода к следующему.
- Логотип — только SVG из `public/brand`. Название пишется «НевГаз» (в логотипе капсом «НЕВГАЗ»). Не «Нефгаз».
- Форма на демо ничего не отправляет: валидация + success-state.
- Внизу футера строка «Демо-версия сайта».

## Порядок работы (ориентир по времени, всего ~5 ч)
1. (20 мин) Global CSS, шрифты, Base layout, Header (вкл. мобильное меню), Footer, заглушки страниц.
2. (90 мин) **Хиро** по выбранной концепции + полоса доверия. Показать результат, дождаться ок.
3. (90 мин) Блоки 3–7: направления, процесс, газификация, цены, работы с лайтбоксом.
4. (45 мин) Блоки 8–14: о нас, отзывы, география, FAQ, форма, контакты.
5. (30 мин) Анимации появления, плавающая кнопка, модалка, SEO/Schema/OG.
6. (25 мин) Проход по мобилке на всех брейкпоинтах, Lighthouse, фиксы, деплой.

## Деплой
Пуш в `main` → GitHub Actions (`.github/workflows/deploy.yml`) собирает и публикует на **GitHub Pages**. В настройках репозитория: Settings → Pages → Source: **GitHub Actions**. Базовый путь берётся автоматически из имени репозитория (`BASE_PATH`), поэтому все внутренние ссылки и пути к `public/` — через `import.meta.env.BASE_URL` (хелпер `url()` в `src/lib/url.ts`).
