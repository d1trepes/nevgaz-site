# 06 · Мобильная версия, адаптив и производительность

Мобилку делаем отдельным этапом (чат 3), когда десктоп главной утверждён. Но с первого дня верстаем без фиксированных ширин, чтобы мобилка была доводкой, а не переделкой.

## Брейкпоинты
`≤ 599` телефон · `600–899` большой телефон / маленький планшет · `900–1079` планшет · `≥ 1080` десктоп. Проверять: 375×667 (iPhone SE), 390×844, 412×915, 768×1024, 1024×768, 1366×768, 1440×900, 1920×1080.

## Общие правила мобилки
- Поля 16px, сетка 4 колонки, gap 16px. Никакого горизонтального скролла страницы (искать причину, а не прятать `overflow-x`).
- H1 на телефоне `clamp(46px, 12.5vw, 64px)`, H2 `clamp(32px, 8.5vw, 44px)`, текст 16px, подписи не мельче 13px.
- Смысловые переносы проверять и на мобилке: при необходимости свои `<br class="m-only">` / `&nbsp;`.
- Тап-зоны ≥ 44×44. Ховеры только в `@media (hover: hover)`.
- Горизонтальные ряды карточек → `scroll-snap` свайп с видимым краем следующей карточки (peek 12–16%), без JS-слайдеров.
- Скругления на телефоне: большие блоки 20px, карточки 18px, фото 14px.
- Кнопки во всю ширину только в формах и в финальном блоке; в остальных местах — по содержимому.
- Безопасные зоны iOS: `env(safe-area-inset-*)` для sticky-шапки и плавающей кнопки.

## Производительность (Lighthouse mobile ≥ 90 по всем 4 метрикам)
- LCP ≤ 2.5с, CLS ≤ 0.05, INP ≤ 200мс, JS на главной ≤ 60 КБ gz.
- Картинки только через `astro:assets` (`<Picture>` AVIF+WebP, `widths=[480, 768, 1080, 1440]`, честные `sizes`). Слой `base.jpg` хиро — `loading="eager" fetchpriority="high"`; остальные слои хиро — `loading="lazy"` и `decoding="async"`, они нужны только после клика.
- На телефоне слои хиро грузить в ширине 768.
- Шрифты self-host; preload только Fira Sans Extra Condensed 700 (cyrillic).
- Карта 2ГИС — только по клику.

## Доступность
Контраст AA, видимый `:focus-visible`, skip-link, `aria-pressed` на выключателях (уже в прототипе), `aria-live` у плашки хиро, `lang="ru"`, заголовки по порядку, у полей формы `label`.
